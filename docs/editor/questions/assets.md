# Kēne Asset 管理问答文档

## 1. 文档用途

这是一份可以单独交给 Chat 使用的产品设计问答文档。目标不是立刻产出代码或一张理想化界面图，
而是通过逐题问答确定 Kēne Editor 的 Asset 管理合同、主要交互和安全边界。

Chat 应把本文中的“当前实现”视为事实，把“已决定”视为约束，把“待讨论问题”视为仍可选择的方向。
不要把推荐项误写成已经实现的功能。

## 2. 给 Chat 的工作方式

请按以下方式与用户讨论：

1. 一次只问一个问题，不要一次要求用户回答整张表。
2. 每题给出 2–3 个有实质差异的方向，并说明用户可见结果、工程复杂度和失败风险。
3. 推荐项必须解释原因，但允许用户组合或提出第四种方案。
4. 用户回答后，先复述本题决定，再进入下一题。
5. 明确区分文件、逻辑 Asset ID、Manifest 记录和运行时资源；不要混称为“素材”。
6. 不设计主题、插件市场、云素材库或协作系统，除非用户明确扩大范围。
7. 不生成代码。问答结束后输出一份决策表、主流程、异常流程和待验证清单。

可直接使用的开场提示：

> 我们要细化 Kēne Editor 的 Asset 管理。请先阅读本文，承认当前实现和已决定事项，随后一次只问一个待讨论问题。每题给出方向、取舍和推荐，不要把未决定内容写成既成事实，也不要开始实现。

## 3. 产品与技术背景

Kēne 是原生视觉小说引擎与编辑器。Eiyashou 工程以源码为权威，常规作者工程包含：

```text
config.yaml
assets.yaml
characters.yaml
scripts/**/*.shou
assets/**
```

资源路径必须留在工程或已声明的只读 Content Mount 根目录中，不能通过绝对路径或 `..` 逃逸。
运行时消费 Loader 解析后的类型化资源，不读取 Editor 私有数据库。

主要资源类型包括：

- Background：背景图；
- Figure：立绘；
- Voice：语音；
- BGM：背景音乐；
- SE / Effect：音效；
- Video：视频。

本轮只覆盖以上六类。Particle、LUT 等类型必须等语言与运行时出现真实需求后再讨论，不能为了完整感
提前扩张 Asset schema 和 UI。

生产图片以 WebP 为规范格式，独立音频以 Ogg Opus 为规范格式，发行视频使用 MP4
（H.264 + AAC）。当前 Asset 入口只接收内容实际有效的这些规范格式；扩展名只能用于预筛选，
不能把伪装扩展名当成有效资源。PNG、JPEG、WAV、MP3、Vorbis、FLAC 等转换能力整体后移。

## 4. 当前 Asset Browser 是什么

当前 Editor 已有一个可从活动栏打开的 Asset 工具视图：

- 作为可关闭的 singleton 工具出现；单独存在时使用标题区，不伪装成文档标签页。
- 从当前 Eiyashou Authoring Index 读取 `assets.yaml` 中的记录。
- 每行显示资源类型、Asset ID、相对路径和引用次数。
- 文件缺失时路径使用错误色。
- 点击某一行会打开并定位到资源 Manifest。
- 与 Explorer、文档编辑器、Inspector、Problems 和 Preview 位于同一 Dock 工作台。

当前尚未提供：

- 从外部导入文件；
- 缩略图、音频试听或视频预览；
- 搜索、过滤、排序和分组；
- 新建、重命名、移动、替换和删除资源；
- 未登记文件扫描、重复内容检测和批处理；
- 转码参数、导入报告和发布就绪状态；
- 直接在 Asset Browser 内修复 Manifest 或脚本引用。

这些都是可能方向，不是默认承诺。

## 5. 已决定事项

### 决定 A1：文件 + Manifest 混合管理

已选择以下方向：

- 工程文件保存真实资源；
- `assets.yaml` 保存稳定的逻辑 ID、资源类型和相对路径；
- 脚本优先引用逻辑 ID，而不是依赖容易变化的文件名；
- Explorer 管物理文件和整个项目结构；
- Asset Browser 管可被作品引用的逻辑资源，并从文件与 Manifest 的当前事实派生问题；
- 不引入封闭的二进制资产数据库。

系统不为导入过程增加 `Pending`、`Needs reconciliation` 或类似生命周期状态。有效资源直接进入
Asset；无效输入直接失败；普通未登记文件只留在 File；用户主动解除映射的文件才进入 `.unmapped`。
缺失文件、格式错误、类型冲突和引用错误是从当前事实产生的诊断，不是另一套可持久化 Asset 状态。

### 决定 A2：按类型唯一的映射

- Asset ID 在各自 Type 命名空间内唯一；
- 同一 Type 内，一个物理文件不能被多个 Asset ID 指向；
- 同一个物理文件允许被不同 Type 显式引用，以保留现有合法项目；
- Asset 可以被任意数量的脚本位置引用。

### 决定 A3：只接收合规格式

- 本轮不转码，也不提供编码参数；
- 文件内容验证通过后才允许复制或登记；
- 无效或非规范输入不产生文件副本、Manifest 记录或中间状态；
- 自动转码与源文件保留策略推迟到后续独立阶段。

### 决定 A4：界面与编辑边界

- File 与 Asset 共用左侧槽位，Editor 位于中央，Inspector 位于右侧；
- Asset 是向内容 Editor 投放资源的唯一入口；
- File 中已有资源不能直接拖入内容 Editor 创建 Block；
- Asset Type 修改只在全部引用兼容时成功，否则整个操作失败关闭；
- Toast、Tasks、图标、文字和动画遵守本文末尾的简洁与性能约束。

## 6. 目标主流程

已经确认的当前阶段主流程是：

```text
选择或拖入外部文件
  -> 验证真实内容与规范格式
  -> 从明确的目标上下文确定 Asset Type
  -> 从文件名生成当前 Type 内唯一的 Asset ID
  -> 原子写入文件与 Manifest
  -> 重新验证引用
  -> 在 Asset Browser、Inspector 和 Problems 中显示结果
```

类型不明确或验证失败时直接拒绝，不进入暂存区。任何失败都不能留下半份文件、悬空 Manifest
记录或已经修改但未能保存的脚本引用。

## 7. 待讨论问题

### Q1. Asset Browser 的角色是什么？

**状态：已回答。选择 B。**

- A：文件浏览器增强版。
- B：文件 + Manifest 混合管理。
- C：由 Editor 完全控制的资产数据库。

后续问题均以 B 为前提。

### Q2. 外部资源导入后如何处理？

**状态：已回答。当前阶段只允许有效的规范格式直接进入，不进行转换。**

- A：原样复制。最可预期，但可能把发布问题推迟到最后。
- B：导入时规范化。符合规范的直接复制，其余资源在确认后转换为生产格式。
- C：源文件和生产文件双轨保存。可重新导出，但增加体积和派生状态管理。

方向 B、C 涉及的转换和派生文件管理已后移。当前阶段不允许用“开发兼容输入”绕过生产格式合同。

### Q3. 如何确定资源类型？

- A：完全依赖目标目录推断。
- B：Editor 先根据文件、目录和当前操作建议类型，用户在导入摘要中确认。
- C：导入后先进入“未分类”，之后再手动整理。

**建议方向：B。** 同一个图片可能是背景、立绘或粒子贴图，不能只根据扩展名做不可撤销判断。

### Q4. Asset ID 如何产生？

- A：始终由用户输入。
- B：由文件名生成可编辑建议，并实时检查当前类型命名空间中的冲突。
- C：使用不可读的随机 ID，显示名另存。

**建议方向：B。** ID 应稳定、适合脚本阅读，并允许不同资源类型使用各自命名空间。

### Q5. 导入目标路径如何决定？

- A：严格放入规范目录，例如 `assets/background/`。
- B：默认使用规范目录，但允许用户选择工程内其他受限路径。
- C：保持外部目录结构。

**建议方向：B。** 默认帮助项目整洁，同时尊重已有工程结构；任何路径都必须留在工程根或合法 Mount 内。

### Q6. Asset Browser 默认如何呈现资源？

- A：紧凑表格，信息密度最高。
- B：缩略图网格，视觉识别最快。
- C：按类型切换紧凑列表与缩略图网格。

**建议方向：C。** 音频、脚本引用状态适合列表；背景和立绘适合缩略图。需要避免为了网格制造大卡片和大留白。

### Q7. 选择 Asset 后由谁显示细节？

- A：Asset Browser 内展开行。
- B：统一交给 Inspector，Asset Browser 只负责集合浏览和选择。
- C：弹出独立详情窗口。

**建议方向：B。** 保持一个选择事实和一个属性区域，避免卡片展开与 Inspector 重复显示同一信息。

### Q8. 重命名、移动或更换文件时如何处理引用？

- A：只修改 Manifest，脚本继续引用稳定 ID。
- B：显示变更预览，同时修复所有显式路径引用和必要的 Manifest 记录。
- C：禁止移动已被引用的资源。

**建议方向：按引用形式区分 A 与 B。** ID 引用不应被无意义重写；显式路径引用必须进入可审核的事务化变更。

### Q9. 删除资源的安全策略是什么？

- A：有引用时禁止删除。
- B：显示引用位置，允许用户取消、仅移除 Manifest、替换引用或确认删除。
- C：移动到工程内回收站，之后再清理。

**建议方向：B，并优先采用可恢复的文件操作。** 不能用一个通用确认框掩盖不同后果。

### Q10. 如何处理重复资源？

- A：只比较路径和文件名。
- B：导入时计算内容摘要，提示相同内容并允许复用现有 ID。
- C：自动合并所有内容相同的文件。

**建议方向：B。** 自动合并可能破坏作者对目录、命名和未来替换的意图。

### Q11. 未登记与缺失资源如何呈现？

- A：全部放进普通列表，仅使用颜色区分。
- B：在统一列表中提供状态过滤，并在 Problems 中生成可导航问题。
- C：用独立“修复中心”承载。

**已确认约束：不增加 Asset 生命周期状态。** File 显示普通文件，Asset 提供 Type、Folder 与
`.unmapped` 视图，缺失或冲突由 Problems 生成可导航诊断。必要标记可以使用图标和最短文字，
不能只靠颜色，也不能在多个位置复制同等重量的信息。

### Q12. 批量导入如何确认？

- A：逐个弹窗确认。
- B：先生成一张批量摘要，允许按行修正类型、ID、路径和转换策略，再一次提交。
- C：全部按全局默认值静默执行。

**建议方向：B。** 提交必须是有界、可取消、尽量原子的任务，进度只能来自实际工作。

### Q13. 转码参数由谁决定？

- A：Editor 内置固定参数。
- B：按资源类型提供少量产品级 preset，并显示预计结果。
- C：暴露编码器的全部技术参数。

**状态：后移。** 当前阶段不实现转码，因此不设计参数、preset、报告或派生状态。

### Q14. 如何定义“发布就绪”？

- A：文件存在即可。
- B：分别展示“可在开发环境预览”和“符合正式发布合同”。
- C：直到执行发布命令才检查。

**建议方向：B。** 兼容输入可以正常开发，但必须清楚标记为尚未满足生产格式，不能显示假成功。

### Q15. 大型项目的扫描策略是什么？

- A：每次打开窗口都全量扫描、解码和计算摘要。
- B：先显示 Manifest 索引，后台按需加载缩略图；文件变化后增量失效。
- C：维护 Editor 私有的永久数据库。

**建议方向：B。** 需要明确缓存位置、上限、失效规则和“缓存不可用不影响工程真实性”的原则。

## 8. 问答完成后应输出什么

最终方案至少应包含：

- Asset、文件、Manifest、引用和派生文件的权威关系；
- 单个导入、批量导入、重命名、移动、替换和删除流程；
- Asset Browser 与 Explorer、Inspector、Problems、Preview 的分工；
- 缺失、未登记、重复、格式不符和转换失败的恢复方式；
- 会修改哪些文件，是否支持撤销，如何避免半完成状态；
- 小项目与大型项目的响应速度和缓存边界；
- 哪些决定只涉及 Editor，哪些需要 Loader、Media、Publisher 或运行时接口变化；
- 必须进行的真实 UI、媒体质量、跨平台路径和发布验证。

## 9. 明确禁止的捷径

- 不允许引用工程外绝对路径作为正式资产。
- 不允许静默有损转换。
- 不允许让缩略图缓存或 Editor 数据库成为工程的唯一事实来源。
- 不允许只改文件、不更新必要引用，或只改 Manifest、不检查文件。
- 不允许用绿色状态掩盖“只能开发预览、不能正式发布”。
- 不允许因为新增 Asset UI 就引入通用插件框架或主题系统。
- 不在 UI 帧内扫描文件系统、解析完整 Manifest 或解码不可见缩略图。
- 不建立常驻轮询、无上限缓存、通用任务框架或与当前六类资源无关的扩展点。
- 能用现有图标清楚表达的操作不堆叠文字；Tooltip 和错误提示只保留完成判断所需的最少内容。
- 点击结果必须立即生效；短过渡只表现结果，不能阻塞操作或制造可感知迟滞。
